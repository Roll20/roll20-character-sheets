Help & Documentation

Sheet v0.21.54.22.19 Core Ability Refresh Build — Built for play, not paperwork. Open the section you need.

Classes is where you define the character: Race, original Class, Level, class structure and character details. Class selection generates the appropriate class information and abilities.

Core is the play surface. It brings together HP, AC, movement, attributes, readied attacks, memorized spells and frequently used class actions without making you hunt through the rest of the sheet.

Combat, Inventory, Magic and Abilities are the management pages. Changes made there feed the useful results back to Core.

Tools contains the Attribute Generator, SIEGE Engine targets, roll options and Character Maintenance.

Design rule: enter or manage information once; the sheet surfaces it wherever it is useful.

The Classes page is the authoritative home for Race, original Class and original Level. Prime, HP progression, BtH, XP requirements, weapons and armour information are derived from the selected class.

Current XP is the character's running experience total. Next Level and Remaining are calculated from the class progression. Use Adjust XP to add or subtract an amount without having to remember the previous total.

Whole-number fields are cleaned when entered so common separators such as commas do not become part of the stored number.

Level changes may surface class progression information and, where implemented, HP gain rolls. The sheet does not remove HP when a level is reduced. HP remains player-controlled rather than letting the sheet silently rewrite the character.

Single Class uses the original Class and Level as the character's class context.

Dual Class represents an established character who later begins another class. The sheet keeps the original and new class records distinct so class-owned checks, abilities and other derived information can use the correct class level.

Enhanced / Class-and-a-Half keeps one principal class and adds the PHB supporting-class package. Supporting level is half the principal level, rounded down. Only abilities allowed to the supporting class package are generated; it is not treated as a complete second class.

Multi-Class is a separate structure in which classes advance together. The sheet presumes the class combination has been approved by the Castle Keeper rather than policing allowed combinations.

Class Plus and Reclass are reserved for later implementation.

Attributes can be marked Primary, Secondary or optional Tertiary. Their challenge bases are configured in Tools → SIEGE Engine.

When the sheet rolls an attribute or class-owned check, it uses the applicable attribute modifier and the class level that actually owns the ability. Situational modifiers and Castle Keeper judgement remain human decisions.

The Attribute Generator in Tools rolls candidate ability-score sets to chat. It does not overwrite the character's attributes.

Inventory owns an Inventory-linked weapon's intrinsic properties, including its 1H/2H damage, Magic Bonus, attack/damage attributes, specialization state, range and notes. Combat uses those properties with the character's live combat values. Manual Combat-only weapons remain independent.

Readied attacks are surfaced on Core so normal combat does not require changing tabs. The weapon attack modifier is built from Best BtH + attack attribute modifier + attack Misc + Magic Bonus + Weapon Specialization. Damage uses the weapon damage expression plus damage attribute modifier + damage Misc + Magic Bonus + Weapon Specialization.

Attack rolls keep the natural d20 separate from the calculated modifier and final total. The roll owns the arithmetic; the chat card reports the result rather than recalculating it independently.

Characters with the Monk Hand-to-Hand Combat ability automatically receive Strike as an always-readied combat option. Its primary, secondary and tertiary damage entries, movement and Monk armour class progression follow the effective Monk level.

Inventory tracks possessions, quantity, weight, encumbrance value, carried state and equipped state. Carried items and coinage feed the Load summary; equipped armour and shields feed the armour-class calculation.

For items marked Weapon, Inventory is the source of truth for intrinsic weapon properties. An equipped Inventory weapon is mirrored into Combat. Change its Magic Bonus, damage expressions, attributes, specialization, range or notes in Inventory rather than maintaining a second copy in Combat.

Armour Class is built transparently from Base AC, armour, shield, applicable modifier, magic and miscellaneous adjustments. Class-specific rules such as Monk armour class can supply the appropriate class base before the applicable Dexterity modifier.

Coinage tracks PP, GP, EP, SP and CP. Total Coins is calculated automatically. Using the C&C PHB guidance that a coin weighs about one ounce, the sheet uses approximately 16 coins = 1 lb and adds coin weight to Carried Weight.

Coinage is deliberately bookkeeping, not banking: the sheet does not automatically exchange denominations or spend money for you.

Magic is the character's spellbook and spell-management page. Memorized spells are surfaced on Core for quick use during play.

Spell resources belong to their caster class. Spells-per-day totals are derived from the supported class progression and applicable bonus spells; remaining uses preserve the number of spells spent when daily capacity changes. Newly gained slots become available; recalculation at unchanged capacity does not refill expended spells.

Cast spends the tracked resource where appropriate. Restore returns the pool to its calculated total when the player intends to restore spells.

The sheet does not invent a universal spell-save DC. C&C saving throws remain part of the SIEGE Engine and the spell's actual rules.

Class Abilities are generated from the character's class records. Their source badge shows which class owns the ability. Buttons distinguish checks and rolls from passive, combat, resource, target-save and informational abilities.

Racial Abilities are generated separately from class structure. Custom Abilities belong to the player and are preserved when generated class information changes.

The sheet automates arithmetic and repeatable bookkeeping where useful, but it does not try to replace descriptive abilities or Castle Keeper adjudication with a button.

Turn Undead is surfaced on Core when the character has access to the Cleric turning ability. The action uses the character's applicable turning level and prompts for situational information needed for the attempt.

The sheet handles the repeatable arithmetic; the Castle Keeper still determines the creatures affected and resolves circumstances that depend on the encounter or the rules text.

Tools contains roll and SIEGE Engine options, the Attribute Generator and Character Maintenance utilities.

Character Builder provides a guided starting-character workflow and hands the completed choices to the existing Race and Class engines. After a character has been applied, reopening the Builder requires the explicit rebuild warning step.

Rebuild Character refreshes generated and derived sheet information from the character's existing source data. Use it when class, race, equipment, spell or Core information appears stale after a change.

Maintenance tools are intended to repair derived sheet state, not replace player-owned character information such as HP, possessions or custom abilities.

Core & presentation: compact graphite/red interface, integrated character-name header, active class/level summary, narrower section bars, readied attacks and synchronized class/racial actions.

Class engine: PHB class data, level/XP progression, Single, Dual and Multi-Class foundations, Best BtH across active classes, class-owned ability levels and corrected Core ability grouping for multi-class characters.

Character Builder: guided race/class/attribute setup, multiple attribute-generation methods, assignment tracking, apply-to-character workflow and rebuild safety lock.

Weapons: Inventory-to-Combat mirroring, duplicate-row reconciliation, 1H/2H damage support, separate attack/damage attributes, Magic Bonus, Weapon Specialization, range/notes and readied-weapon surfacing on Core.

Weapon math: Best BtH, attribute, Misc, Magic and Specialization are reconciled into the displayed Combat modifier. Inventory-linked Magic is controlled by Inventory rather than edited independently on Combat.

Other systems: Inventory/Load/coinage, transparent AC construction, Turn Undead, spellbook/memorized-spell support, racial abilities, class abilities and maintenance/rebuild utilities are present in the current test line.

Core vs Combat parity: roll the same readied weapon from both pages and verify identical attack and damage modifiers, including Magic Bonus and Weapon Specialization.

Weapon regression matrix: verify specialization on/off, Magic 0/positive, STR/DEX/None, Misc modifiers, 1H/2H damage, manual Combat-only weapons and Inventory-linked weapons.

Class structures: continue regression testing Single, Dual and three-class Multi-Class characters for BtH, current class levels, ability ownership, XP/progression and spell resources.

Roll20 environment: continue testing in the live Roll20 sheet environment as well as Sheet Sandbox, including responsive layouts and dark mode.

Character Builder: continue guided setup and polish after the current mechanics are stable.

Weapons: broader weapon-property automation/library support and continued cleanup of the Inventory/Combat workflow after tester feedback.

Magic: manual Spellbook sorting, preferably drag-and-drop while preserving repeating-row IDs and spell data, with simple up/down controls as a fallback; improve Core spell presentation and attack-spell damage handling.

Classes: continue Dual/Multi-Class edge-case work and later Class Plus/Reclass support.

Appearance: complete dark-mode and responsive-layout testing/polish.

Authoring: future class-authoring toolkit for custom C&C classes. This remains long-term scope and will not hold up the current sheet.

Release: incorporate outside tester feedback, finish migration/repair notes and prepare the sheet for wider community/public distribution.

The sheet is designed to make its arithmetic inspectable. Derived values come from the character's authoritative source data rather than becoming separate rules that drift away from the character.

Weapon attack: Best BtH + attack attribute modifier + attack Misc + Magic Bonus + Weapon Specialization. Weapon damage: damage expression + damage attribute modifier + damage Misc + Magic Bonus + Weapon Specialization.

Class-owned mechanics use the class and effective level that grant them. This matters for structures such as Dual Class and Class-and-a-Half, where two abilities on the same character may legitimately use different class levels.

Automation stops where judgement begins. The sheet can calculate a modifier, resource or progression; the player and Castle Keeper still decide circumstances, targets, permissions and outcomes that the rules leave to play.

If generated class, race, equipment, spell or Core information looks stale after a change, use Tools → Character Maintenance → Rebuild Character.

Rebuild regenerates derived information from the character's source data. It is not intended to erase player-entered custom abilities, possessions, HP or other character state.

If something still looks wrong, record the character's Race, class structure, classes and levels, what you expected, what the sheet displayed, and the action that produced it. That gives us a reproducible test instead of a mystery.
